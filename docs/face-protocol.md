# Протокол агент ⇄ мордашка

Агент `yuka-agent` и графическая мордашка (`yuka-agent-desktop-ui`) обмениваются данными
через Unix-сокет. Формат — **NDJSON**: один JSON-объект на строку, `\n` в конце, UTF-8.
Агент — сервер, мордашка подключается к пути из `$YUKA_SOCKET` (или к `/tmp/yuka-dev.sock`
в режиме `YUKA_FACE=attach`).

Версия 2 добавляет **инструменты**: мордашка сообщает агенту, что она умеет (сменить
тему, спрятать панель…), а модель вызывает эти действия, когда пользователь просит.
Форма сообщений повторяет [MCP](https://modelcontextprotocol.io) (`tools/list`,
`tools/call`): имена полей, JSON Schema аргументов, аннотации и формат результата
совпадают, поэтому переход на полноценный MCP сводится к смене транспорта.

**Совместимость.** Обе стороны игнорируют незнакомые типы сообщений и поля.
- Агент v2 с мордашкой v1: мордашка не присылает `capabilities` — инструментов нет, всё
  работает как раньше.
- Агент v1 с мордашкой v2: в `hello` нет `protocol: 2`, поэтому мордашка не присылает
  `capabilities`.

---

## Сообщения версии 1 (без изменений)

| Направление | `type` | Поля | Смысл |
|---|---|---|---|
| агент → мордашка | `hello` | `agent: {name, model}`, `greeting` | начало сессии |
| агент → мордашка | `assistant_start` | `id` | начало ответа |
| агент → мордашка | `assistant_chunk` | `id`, `text` | очередной кусок ответа |
| агент → мордашка | `assistant_end` | `id` | ответ закончен |
| агент → мордашка | `error` | `message` | ошибка хода (идёт после `assistant_end`) |
| агент → мордашка | `bye` | — | агент завершает работу |
| мордашка → агент | `user_message` | `text` | сообщение пользователя |

## Что добавляет версия 2

### `hello.protocol`

```json
{"type":"hello","protocol":2,"agent":{"name":"Юка","model":"qwen2.5:7b"},"greeting":"…"}
```

### `capabilities` (мордашка → агент)

Мордашка присылает этот набор после `hello` и может присылать его повторно в любой момент.
Каждое сообщение **полностью заменяет** набор инструментов мордашки (аналог MCP
`notifications/tools/list_changed`). Пустой список убирает все инструменты.

```json
{
  "type": "capabilities",
  "protocol": 2,
  "instructions": "Ты управляешь своим интерфейсом на рабочем столе Юры…",
  "tools": [
    {
      "name": "ui_set_theme",
      "title": "Сменить тему",
      "description": "Меняет тему интерфейса. Вызывай, когда Юра просит другую тему или цвет.",
      "inputSchema": {
        "type": "object",
        "properties": { "mode": { "type": "string", "enum": ["auto", "morning", "day", "evening", "night"] } },
        "required": ["mode"],
        "additionalProperties": false
      },
      "annotations": { "readOnlyHint": false, "destructiveHint": false, "idempotentHint": true }
    }
  ]
}
```

| Поле инструмента | Обязательное | Смысл |
|---|---|---|
| `name` | да | `^[a-z][a-z0-9_]{0,63}$`, уникально в наборе |
| `title` | нет | короткое имя для людей (статус в терминале и в панели) |
| `description` | да | для модели: что делает и когда вызывать |
| `inputSchema` | да | JSON Schema аргументов, `type: "object"` |
| `annotations.readOnlyHint` | нет | ничего не меняет |
| `annotations.destructiveHint` | нет | необратимо или заметно для пользователя: **мордашка сама спрашивает подтверждение** |
| `annotations.idempotentHint` | нет | повтор с теми же аргументами ничего не меняет |

`instructions` — короткий текст для модели о том, как пользоваться инструментами мордашки.
Агент добавляет его в системный промпт.

Инструмент с некорректным описанием (нет `name`, `description` или схема не объект)
агент отбрасывает с предупреждением. Остальные инструменты набора он принимает.

### `tool_call` (агент → мордашка)

```json
{"type":"tool_call","id":"call_3","name":"ui_set_theme","arguments":{"mode":"night"}}
```

### `tool_result` (мордашка → агент)

```json
{"type":"tool_result","id":"call_3","content":[{"type":"text","text":"Тема: ночь"}],"isError":false}
```

При `isError: true` в `content` лежит понятное модели описание ошибки: неверные аргументы,
пользователь отказался и т. п.

## Правила вызова

- `id` уникален в пределах сессии. На каждый `tool_call` приходит **ровно один**
  `tool_result` с тем же `id`.
- Мордашка проверяет аргументы по `inputSchema`. Неверные аргументы дают `isError` с текстом,
  по которому модель может исправить вызов.
- Для `destructiveHint` мордашка спрашивает пользователя («Да / Нет») и только после «Да»
  выполняет действие. Отказ или молчание дают `isError: true` с текстом «пользователь
  отказался».
- Таймаут ожидания `tool_result` на стороне агента: **10 с**, для `destructiveHint` —
  **60 с**, потому что ждём человека. После таймаута поздний `tool_result` игнорируется.
- Пока агент ждёт `tool_result`, мордашка может прислать `user_message` или `capabilities`.
  Сообщение пользователя ставится в очередь и обрабатывается следующим ходом, новый набор
  инструментов применяется сразу.
- Если сокет закрылся во время ожидания, вызов завершается ошибкой «интерфейс закрыт».

## Ход с инструментами

Все вызовы модели одного хода показываются как **один** ответ: `assistant_start` в начале,
`assistant_end` в конце. Между ними могут идти `tool_call` и `tool_result`.

```
мордашка  user_message "включи ночную тему"
агент     assistant_start {id:4}
агент     tool_call {id:"call_1", name:"ui_set_theme", arguments:{mode:"night"}}
мордашка  tool_result {id:"call_1", content:[{text:"Тема: ночь"}]}
агент     assistant_chunk {id:4, text:"Готово, "} …
агент     assistant_end {id:4}
```

За один ход модель вызывается не больше 4 раз. Если лимит исчерпан, ход завершается
ошибкой.

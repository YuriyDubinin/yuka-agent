# Yuka Agent

ИИ-агент на C++17 поверх локальной LLM. При старте Юка загружает базовые знания о себе
и о пользователе из `storage/yuka.json`, а затем общается через Ollama Chat API
(`POST /api/chat`, потоковый режим) с системным промптом из этого файла. Контекст диалога
сохраняется в течение сессии.

Общаться с Юкой можно через разные **мордашки** (интерфейсы). Если рядом с бинарником
лежит графическая мордашка (например, приложение из
[`../yuka-agent-desktop-ui`](../yuka-agent-desktop-ui)), Юка запускает её, здоровается
и ведёт весь разговор через неё. Если подходящей мордашки нет, Юка работает в терминале.

| Что | Имя |
|---|---|
| Бинарник агента | `build/yuka-agent` |
| Графический интерфейс, который ищет агент | `build/gui/yuka-agent-desktop-ui.app` (рядом с бинарником, в каталоге `gui/`) |

## 1. Что должно быть установлено

| Компонент | Зачем | Установка (macOS) |
|---|---|---|
| Xcode Command Line Tools (clang++ с C++17) | компиляция | `xcode-select --install` |
| curl | HTTP-запросы к Ollama | есть в macOS |
| CMake ≥ 3.15 | сборка | `brew install cmake` |
| Ollama | запуск модели | `brew install ollama` |
| Модель `qwen2.5:7b` (~4.7 ГБ) | сама LLM | `ollama pull qwen2.5:7b` |
| clang-format *(опционально)* | форматирование кода (`refmt.sh`) | `brew install clang-format` |

> Платформа: macOS. Программа использует `osascript` и Terminal.app.

- - -

## 2. Проверка окружения

```bash
clang++ --version        # компилятор
cmake --version          # должно быть >= 3.15
which ollama             # путь к ollama, например /opt/homebrew/bin/ollama
ollama --version
```

Проверка модели (нужен запущенный сервер Ollama):

```bash
ollama serve             # в отдельном окне терминала, если сервер ещё не запущен
ollama list              # в списке должна быть qwen2.5:7b
```

Если `ollama list` пишет `could not connect to ollama server`, значит сервер не запущен
(см. `ollama serve` выше).

- - -

## 3. Сборка

Из корня проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Бинарник: **`build/yuka-agent`**.

При первой конфигурации CMake скачивает [nlohmann/json](https://github.com/nlohmann/json)
v3.12.0 (через `FetchContent`, с проверкой SHA256), поэтому нужен интернет.

Чтобы общаться через окно, установите десктопную мордашку (подробности в
[`../yuka-agent-desktop-ui/README.md`](../yuka-agent-desktop-ui/README.md)):

```bash
cd ../yuka-agent-desktop-ui && npm install && npm run build
mkdir -p ../yuka-agent/build/gui && cp -R release/yuka-agent-desktop-ui.app ../yuka-agent/build/gui/
```

- - -

## 4. Запуск

```bash
./build/yuka-agent
```

Как ведёт себя программа:

- Если `ollama serve` не запущен, она сама поднимает его в фоне. Лог пишется
  в `/tmp/yuka-ollama-serve.log`.
- Если найдена графическая мордашка, Юка открывает окно, здоровается **в окне** и дальше
  общается только через него. Терминал показывает лишь статус:

  ```
  Нашла мордашку «desktop-ui» (неплохой электроновский интерфейс), запускаю...
  Юка открыта в отдельном окне. Закрой окно или нажми Ctrl+C, чтобы выйти.
  ```

- Если мордашек нет или ни одна не запустилась, Юка сообщает причину и здоровается
  в терминале. Если запуск идёт **не из Terminal.app** (iTerm, VS Code, CLion и т.п.),
  она откроет новое окно Terminal.app и перезапустится там. Чтобы остаться в текущем
  терминале:

  ```bash
  YUKA_IN_SYSTEM_TERMINAL=1 ./build/yuka-agent
  ```

В терминале после `Вы: >` введите сообщение и нажмите Enter. Ответ печатается по мере
генерации. Первый ответ может прийти с задержкой, пока модель загружается в память.

### Приветствие

Приветствие собирается из `greeting.base` и варианта, который зависит от того, как
началась сессия:

| Ситуация | Вариант | Пример |
|---|---|---|
| Мордашка найдена и запущена | `with_face` | «Привет, Юра! Это я, Юка. О, мне достался неплохой электроновский интерфейс — так гораздо уютнее!» |
| Мордашек нет или все упали | `without_face` | «… Ни одна мордашка не завелась, так что беру системную — старый добрый терминал.» |
| Терминал выбран явно (`YUKA_FACE=terminal`) | `terminal_chosen` | «… Сегодня болтаем по-простому, в терминале.» |

Юка также знает, через какой интерфейс идёт разговор, и правильно ответит на вопрос
«через что мы сейчас общаемся?».

## Мордашки (интерфейсы)

При запуске `yuka-agent` смотрит в каталог `gui/` **рядом со своим бинарником** и ищет
там `yuka-agent-desktop-ui`. Нашла — запускает графический интерфейс и общается через
него. Не нашла — работает в терминале. Никаких манифестов и настроек не нужно:

```
build/
├── yuka-agent
└── gui/
    └── yuka-agent-desktop-ui.app
```

Что именно ищется в `gui/`, по порядку:

1. `yuka-agent-desktop-ui.app` — macOS-приложение (так собирается Electron-мордашка).
   Запускается его исполняемый файл `yuka-agent-desktop-ui.app/Contents/MacOS/yuka-agent-desktop-ui`.
2. `yuka-agent-desktop-ui` — обычный исполняемый файл.

> Почему `.app`, а не голый бинарник: исполняемый файл Electron не работает отдельно от
> своего бандла (рядом должны лежать фреймворки и ресурсы). В Finder
> `yuka-agent-desktop-ui.app` выглядит как один файл.

Мордашка представляется как «неплохой электроновский интерфейс». Это значение
`{face_title}` в приветствии и в системном промпте, оно задано константой
`k_gui_title` в `src/faces/face_discovery.hpp`.

Как это работает:

1. `yuka-agent` создаёт Unix-сокет `/tmp/yuka-<pid>.sock` (доступ только у текущего
   пользователя) и запускает мордашку с переменной окружения `YUKA_SOCKET`.
2. Мордашка подключается к сокету (на это даётся 30 секунд). Дальше обмен идёт
   JSON-сообщениями, по одному на строку:
   - от агента: `hello` (с приветствием), `assistant_start`, `assistant_chunk`,
     `assistant_end`, `error`, `bye`;
   - от мордашки: `user_message`.
3. Закрыли окно — сессия завершается. Ctrl+C в терминале — Юка прощается (`bye`) и
   закрывает окно.
4. Если мордашка не запустилась или не подключилась, Юка сообщает об этом и
   продолжает работу в терминале. Вывод мордашки пишется в
   `/tmp/yuka-face-yuka-agent-desktop-ui.log`.

Выбор мордашки — переменная `YUKA_FACE`:

| Значение | Поведение |
|---|---|
| не задано / `auto` | `gui/yuka-agent-desktop-ui`, если есть, иначе терминал |
| `terminal` | всегда терминал |
| `attach` | режим разработки: ждать подключения к `/tmp/yuka-dev.sock` |

Каталог `gui/` можно переопределить: `YUKA_GUI_DIR=/path/to/gui ./build/yuka-agent`.

## Хранилище: `storage/yuka.json`

Базовая информация, с которой агент запускается. Файл читается **один раз при старте**,
поэтому после правок перезапустите `yuka-agent` (пересобирать не нужно).

| Поле | Обязательное | Назначение |
|---|---|---|
| `name` | да | Имя агента, отображается в чате |
| `language` | да | Язык общения (сейчас `ru`) |
| `model` | да | Модель Ollama, например `qwen2.5:7b` |
| `user.name` | да | Имя пользователя (`Юра`) |
| `user.relationship` | нет | Кем Юка приходится пользователю: давняя подруга и личный ассистент |
| `identity` | да | Кто такой агент: основа системного промпта |
| `greeting.base` | да | Начало приветствия |
| `greeting.with_face` | да | Продолжение, если запущена графическая мордашка |
| `greeting.without_face` | да | Продолжение, если ни одна мордашка не заработала |
| `greeting.terminal_chosen` | нет | Продолжение, если терминал выбран явно |
| `rules` | нет | Список правил поведения, добавляется в системный промпт |
| `options` | нет | Параметры генерации Ollama (`temperature`, `top_p`, `repeat_penalty`, …) |

Плейсхолдеры в текстовых полях:

| Плейсхолдер | Значение |
|---|---|
| `{name}` | имя агента (`Юка`) |
| `{user}` | имя пользователя (`Юра`) |
| `{model}` | модель (`qwen2.5:7b`) |
| `{face_title}` | как представляется мордашка: «неплохой электроновский интерфейс» (только в `greeting.*`) |

Основные правила личности, заданные в `rules`:

- Юка всегда говорит о себе **в женском роде**;
- пользователя зовут **Юра**, они давно знакомы, Юка общается с ним как давняя подруга,
  **на «ты»**, без «рада знакомству»;
- Юка — **ассистент** Юры и помогает ему с задачами;
- только русский язык, без иероглифов и английских вставок;
- про модель говорит, только если её прямо спросят.

Системный промпт собирается так: `identity` и `user.relationship`, затем пронумерованные
`rules`, затем раздел «Текущая сессия»: с кем идёт разговор, через какой интерфейс и каким
было приветствие.

Путь к каталогу хранилища:

- по умолчанию это `storage/` в корне проекта (путь зашивается при сборке);
- переопределяется переменной окружения `YUKA_STORAGE` (каталог, в котором лежит `yuka.json`):

  ```bash
  YUKA_STORAGE=/path/to/dir ./build/yuka-agent
  ```

Если файла нет, JSON некорректен или не хватает обязательного поля, программа выводит
понятную ошибку и завершается с кодом 1.

> Температура в `options` снижена (0.3), потому что при значениях по умолчанию
> qwen2.5:7b иногда переходит на китайский или вставляет английские слова.

## 5. Остановка

- Выход из чата в терминале: `выход`, `exit`, `quit`, `Ctrl+C` или `Ctrl+D`.
- В графическом режиме: закрыть окно Юки или нажать `Ctrl+C` в терминале.
- Сервер Ollama после выхода **продолжает работать** в фоне. Остановить его:

  ```bash
  pkill -f "ollama serve"
  ```

  Если Ollama установлена как приложение или сервис brew: `brew services stop ollama`.

## Разработка

Форматирование исходников в `src/`:

```bash
./refmt.sh
```

Структура исходников. Каталоги разделены по ролям агента; зависимости идут сверху вниз:
`app → agent, llm, faces → platform`. Заголовки подключаются от корня `src/`, например
`#include "faces/socket/socket_face.hpp"`.

```
src/
├── app/                        точка входа и сценарий запуска
│   └── main.cpp                проверка Ollama, выбор мордашки, Terminal.app, цикл чата, история
├── agent/                      кто такая Юка
│   └── config.{hpp,cpp}        загрузка и валидация default.json, приветствие, системный промпт
├── llm/                        подключение к модели
│   └── ollama_client.{hpp,cpp} потоковый клиент Ollama (/api/chat, /api/tags через curl)
├── faces/                      через что Юка общается
│   ├── face.hpp                интерфейс мордашки, с которым работает цикл чата
│   ├── face_discovery.{hpp,cpp} поиск gui/yuka-agent-desktop-ui рядом с бинарником, путь к бинарнику
│   ├── terminal/
│   │   └── terminal_face.{hpp,cpp} терминальная мордашка (эффект печати, цвета)
│   └── socket/
│       └── socket_face.{hpp,cpp}   графическая мордашка: запуск процесса, Unix-сокет, NDJSON
└── platform/                   обёртки над ОС
    ├── signals.{hpp,cpp}       обработка Ctrl+C
    ├── terminal.hpp            цвета и вывод сообщений в терминал
    └── shell.hpp               экранирование строк для shell
```

Модель меняется в `storage/yuka.json` (поле `model`). Скачайте её заранее
через `ollama pull <model>`.
